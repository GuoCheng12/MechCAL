# 評估指標規格（7 個家族，草稿，待作者確認）

2026-11-14。取代以「前三名」為核心的指標（R@3、nDCG@3、ES-nDCG@3）。適用於重建後的數據集（約 300 個案例）。

## 1. 為什麼要換

機制家族縮減為 7 個之後，平均每個案例有 2.38 個標籤。對每個分子都回答「RIM、ICT、RAD」，就有 R@3 0.68、nDCG@3 0.60（118 個有標籤的案例）。前三名幾乎能覆蓋所有標籤，指標無法區分方法。改成前兩名或只看第一名只是降低數值，沒有解決「猜常見家族就得分」的問題。

## 2. 輸出格式（所有方法相同：MechCAL、Direct、ReAct）

每個案例提交兩樣東西：

1. **聲明的家族**：系統判斷「這個分子被報導有這個機制」的家族，**1 到 7 個**，每個附證據和理由。未聲明的家族視為「沒有聲明」。由系統（MechCAL 是教授）自己決定，沒有固定門檻。
2. **每個家族的機率**：7 個家族各給一個 0–1 的數，表示「被報導」的可能性。MechCAL 取假設板上的可信度；Direct、ReAct 在提交時給出。

主要機制的預測：聲明的家族中機率最高的那個。

## 3. 指標

### 主表

| 指標 | 定義 | 計算單位 | 依賴 |
|---|---|---|---|
| **ES-F1**（主指標） | 對每個分子：TP* = 說中的家族的證據分數 s 之和（s ∈ {0, 0.5, 1}，評審按評分規則給）；ES-F1 = 2·TP* ÷（聲明數 + 參考標籤數）；再對分子平均 | 每個分子 | 標籤 + LLM 評審 |
| 主要機制 Top-1 | 預測的主要機制是否屬於參考答案的主要機制（primary 或 co_primary） | 每個分子（只算有主要標籤的案例） | 標籤 |
| 按家族 MCC | 對每個家族數 TP、FP、FN、TN，MCC = (TP·TN − FP·FN) ÷ √[(TP+FP)(TP+FN)(TN+FP)(TN+FN)]（分母為 0 時記 0）；對 7 個家族平均 | 每個家族，跨分子 | 標籤 |
| Brier 分數 | 對每個分子：7 個家族的 (機率 − 是否在參考答案)² 的平均；再對分子平均。越低越好 | 每個分子 | 標籤 |

### 證據表

| 指標 | 定義 | 依賴 |
|---|---|---|
| 陳述有根據率 | 聲明家族的計算型陳述中，數值能被程序對上計算記錄的比例（反面是編造率）；另報提交前自查之前的數值 | 確定性程序 |
| 證據精確率 | 評審判為「一致」的陳述佔全部陳述的比例 | LLM 評審 |
| 不看證據的 F1，及其與 ES-F1 的差 | 與 ES-F1 相同，但說中一律記 1；差值表示「說對了但證據不夠」的部分 | 標籤（差值另含評審） |

### 可靠性與成本

| 指標 | 定義 | 依賴 |
|---|---|---|
| 重複一致性（pass^k） | 同一分子跑 k 次，k 次的主要機制都預測正確的比例；另報 k 次聲明集合完全相同的比例 | 標籤 + 多次運行 |
| 成本 | 每個分子的 tokens（系統和評審分開）、費用（按高峰／非高峰價格）、工具時間 | 運行記錄 |

重複一致性要和準確率一起看：固定答案的一致性是 1。

### 附錄

- 每個家族的精確率、召回率、F1、MCC 明細和正例數。
- 擾動實驗：對被改動的陳述，數值核對或評審抓出的比例；改寫措辭、調換順序時分數不變的比例。
- 評審與人工的一致度（Cohen's κ），抽樣人工評分。
- 評審換成另一個模型家族後，主表的變化。

## 4. 下限（固定答案，現有 118 個有標籤的案例，7 個家族）

| 指標 | 固定答案的分數 |
|---|---|
| ES-F1 | 0（沒有證據）；只給結構推理時，按評分規則最多拿到每個家族 0.5 |
| 主要機制 Top-1 | 0.38（永遠答 RIM，108 個有主要標籤的案例） |
| 按家族 MCC | 0（任何固定答案都是 0） |
| Brier 分數 | 0.196（按各家族的出現頻率給機率）；全部給 0.5 為 0.250 |
| 不看證據的 F1 | 0.57（永遠答 RIM、ICT、RAD） |

結果表要同時列出這些下限和結構相似度 kNN（按論文留一）的分數。

## 5. 統計和排除規則

- **置信區間**：按論文分群做 bootstrap（每次抽樣後重算全部指標，包括 MCC），報 95% 區間；方法之間做配對比較。
- **排除**：沒有任何標籤的案例不計入（目前是 0064）；沒有主要標籤的案例不計入主要機制 Top-1（目前 10 個）。
- **重複運行**：每次運行算一行；MCC 把所有運行合起來數四種情況。
- **樣本量**：某個家族的正例太少時，它的 MCC 不穩定。現有數據 ESIPT 只有 16 個正例、PET 21 個；重建數據集時建議每個家族至少 25–30 個正例（經驗估計，不是硬標準）。

## 6. 依賴 LLM 評審的程度

9 個指標中：統計 5 個（Top-1、MCC、Brier、不看證據的 F1、重複一致性），確定性程序 2 個（有根據率、成本），依賴評審 2 個（ES-F1、證據精確率）。主表 4 個裡只有 ES-F1 依賴評審，因此評審的可信度（附錄的擾動實驗、人工一致度、換模型家族）必須報告。

## 8. 實現計劃（待作者批准，會改任務定義）

1. 提交格式：聲明家族 1–7 個 + 7 個家族的機率 → 驗證：MechCAL、Direct、ReAct 的離線測試都能產生並解析新格式；舊格式被拒絕。
2. MechCAL：教授在 `submit` 時列出聲明的家族；提交只含聲明的家族；機率取自假設板 → 驗證：離線測試；在非高峰期跑 1–2 個開發案例冒煙。
3. Direct、ReAct：同樣的格式和說明 → 驗證：離線測試 + 冒煙。
4. 評分：新增上述指標的計算和 bootstrap；排除規則 → 驗證：用手算的小例子（每個指標各一個）做單元測試；固定答案的下限和本文第 4 節一致。
5. 文檔：`CLAUDE.md` 的任務定義改為「聲明 1–7 個家族並給證據」，`docs/evaluation-design.md` 引用本文。
