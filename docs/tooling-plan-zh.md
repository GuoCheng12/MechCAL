# 工具與呈現改進計劃（release 0.3.0，開發階段）

狀態：草案，2026-11-12。範圍：開發集上的兩週工作（第 1 週 W1、第 2 週 W2）。
前提：開發集/測試集已固定（`benchmarks/photomechbench/splits/raw_v2_119_dev_test.json`），本計劃的所有運行只用開發集的 17 個案例。

## 0. 目的與原則

**目的**：讓教授（Planner）在充分知情的前提下自主選擇實驗；讓現有工具給不出的證據變得可以計算。最終目標是教授在自我思考下調用工具，得到好的結果和解釋。

**原則**
1. 只提供資訊，不提供判斷：卡片描述工具，不描述機制；不給「家族 → 測試」的對照。
2. 怎麼選完全由教授決定；科學設定歸教授，技術調整歸學生。
3. 所有方法拿同一份卡片（MechCAL、A 組、ReAct 基線）。
4. 工具內部的物理計算可以寫死；替代理做決策的規則不寫死。
5. 工具清單以領域知識為準（每個機制在物理上需要什麼可觀測量），開發結果只作佐證；凡是受開發結果影響的決定，記入 `docs/dev-decision-log.md`。
6. 不讀參考答案和評分標準；不針對單一案例調整。

**這幾輪的依據**（16 次運行：dev1、dev2、0003 smoke-4～7）

| 現象 | 數據 |
|---|---|
| 證據天花板不均 | 評審平均分：RADIATIVE 1.00、ICT 0.96；TRIPLET 0.56；RIM、ESIPT、AGGREGATE 0.50；PACKING、HOST_GUEST、PET、SOKR、RACI 從未被評 |
| 能填補空缺的工具從沒被用過 | 接觸扭轉響應、CIS 座標掃描、S0/S1 受力比較、分子間距離掃描；另有 8 個重疊的 `run_targeted_*` |
| 教授的選擇被呈現方式引導 | 75 次委派中 50 次走配方；工具說明被截斷到 160 個字元 |
| 預算浪費 | 4 次 `not_applicable` 的委派；技術參數被鎖導致的不必要攔截 |
| PySCF 自旋態 | 23 次中 5 次成功：11 次態已算完但穩定性檢查超時；4 次時限內無結果；3 次 SCF 不收斂；5 次片段參數錯誤 |
| 其他工具介面 | 扭轉掃描 8 次失敗、幾何描述量 6 次失敗，全部是參數格式問題 |

## 1. 第 1 週（W1）：呈現層、修補、第一層擴展

### W1.1 靜態能力卡片
- 新增 `mechcal/agent/cards/`：每個對代理可見的工具一份卡片，固定欄位為：
  `computes`（算什麼、方法層級）、`you_can_vary`（科學參數及可選範圍）、`returns`（輸出的量）、`feeds_into`（可接著用的工具）、`scope`（元素、原子數、電荷、閉殼層，以結構化欄位描述）、`does_not_tell`（不能說明什麼）。
- 卡片文字由我依據工具的實際實現和參數定義起草，**由你審閱**；確認後計入凍結清單（雜湊）。
- 卡片不得出現機制家族名稱；用測試檢查這一點。
- **完成標準**：所有可見工具都有卡片；測試保證卡片欄位齊全、參數與工具定義一致、不含家族名稱。

### W1.2 卡片的動態部分
- **適用性**：依卡片的 `scope` 和結構事實（元素、原子數、電荷、電子數奇偶、力場能否建立）計算，在教授第一輪之前生成。
- **成本**：沿用成本模型，但改按基函數數換算，並對過渡金屬單獨記錄；每輪更新。
- **輸入就緒狀態**：例如「需要 amesp_baseline_bundle（目前沒有）」，每輪更新。
- **完成標準**：開發集上 `not_applicable` 的委派次數為 0；成本估計和實際耗時的偏差有記錄可查。

### W1.3 配方降為普通選項
- 配方和工具並列在同一張清單，說明只寫「由哪幾個工具組成」；新增的組合按計算內容命名。
- 教授的工具清單（`_professor_catalog`）和學生的工具卡片都改用 W1.1 的卡片，不再截斷。
- ReAct 基線（`mechcal/eval/grounded_subjects.py`）也改用同一份卡片。

### W1.4 `fixed_args` / `suggested_args`
- 委派時分開：`fixed_args` 只放科學設定（鎖定）；`suggested_args` 放技術起始值（學生可改，需寫明理由）。
- 教授把技術參數寫進 `fixed_args` 時，系統自動移到 `suggested_args` 並告知教授。
- **完成標準**：離線測試涵蓋兩種參數；開發集上不再出現因技術參數被鎖而產生的攔截。

### W1.5 工具修補
| 工具 | 修法 |
|---|---|
| PySCF 自旋態 | ① 時限由成本模型按分子估算，取代寫死的 `PYSCF_SPIN_WALL = 1200`（量自 0003 單一分子）；② 「態已算完、穩定性檢查未完成」單獨標示為可用但未驗證，不再和「無結果」混為一談；③ 從進程日誌識別 SCF 不收斂，歸為 `not_converged`；④ 增加幫助 SCF 收斂的技術參數（例如 level shift、damping），讓學生有可調的空間 |
| 扭轉掃描 | 角度自動換算到 (−180°, 180°]；二面角 ID 和原子同時給且一致時接受；接受 `"1"` 這類 ID 寫法 |
| 幾何描述量提取 | 接受「原子對/三元組/四元組」列表，自動判斷距離/角度/二面角並生成 ID |
| 8 個 `run_targeted_*` | 從代理的工具清單移除（代碼保留） |
| 「不適用」的判斷 | 由卡片的 `scope` 和工具拋出的結構化代碼決定，取代比對錯誤訊息的正則表達式 |

**完成標準**：每項有離線測試；開發集上這些工具的參數格式錯誤次數明顯下降。

### W1.6 第一層擴展（組合現有計算，不需要新後端）
| 新增 | 內容 | 輸出 |
|---|---|---|
| `dimer_excited_states`（組合） | 二聚體構型 → 激發態 → 以兩個單體為片段做空穴–電子分析 | 每個態的激子在兩個單體上的分布、單體間電荷轉移比例、相對單體 S1 的能量位移 |
| `state_descriptors`（由現有結果推導） | 讀取已有的激發態結果 | 由振子強度和能量估算的輻射速率（Strickler–Berg 簡化式，氣相、折射率 1，需標明）；S1、S2 的能隙和各自的振子強度與電荷轉移特徵 |
| 扭轉掃描輸出擴充 | 已有數據的整理 | 每個角度的 S0 相對能量和 S1–S0 能隙 |
| 前線軌道分區 | 工具本身沒有問題（失敗都來自傳錯輸入，已被預檢擋住） | 在卡片中說清楚它給出給體/受體上 HOMO/LUMO 的分布和能級排列 |

**完成標準**：每項有離線測試和一個開發案例上的真實運行；輸出都經過閘道記錄，帶指針、警告和成本記錄。

### W1.7 第 1 週的驗證
- 開發集 17 個案例 × 2 次重複運行（W1.1～W1.6 全部完成之後）。
- 指標：各家族評審分數、各家族被測試的頻率、工具使用分布、`not_applicable` 委派和不必要攔截的次數、nDCG / ES-nDCG 的平均和波動。
- 與 dev2 對比時，只比較原本 6 個案例；新增的 10 個案例作為新的基準線。

## 2. 第 2 週（W2）：第二層擴展與評估流程

### W2.1 ESIPT 互變異構體態比較（新工具）
- 由結構事實裡的分子內氫鍵模式（O–H···N/O）找出質子給體和受體；用 RDKit 生成質子轉移後的互變異構體，保留原子編號。
- 兩個結構各自做 S0 優化（Amesp 原生優化）和激發態計算。
- 輸出：兩者的 S0 和 S1 能量差、S1 的性質。
- 卡片寫明：不是能壘、不是反應路徑；沒有相應氫鍵模式的分子標為不適用。

### W2.2 沿分子間距離的激子耦合
- 用現有的分子間距離掃描產生一系列二聚體幾何 → 每個幾何做激發態計算。
- 輸出：低激發態的分裂隨距離的變化，以及單體間電荷轉移的比例。

### W2.3 片段式 PET 驅動力估計（評估可行性）
- 把分子切成給體和受體片段並封端，分別計算電離能和電子親和能，再結合激發能估算驅動力（Rehm–Weller 型的近似）。
- 先在 2 個開發案例上試做，確認封端方式和數值是否合理，再決定是否加入。

### W2.4 PACKING 小團簇模型（只做成本評估）
- 估算 3–5 個分子的團簇用 xTB 優化和接觸扭轉比較的成本，交給你決定做不做。

### W2.5 評估流程第一次用真實 API
- **基線**：Direct 和 ReAct 在開發集上各跑一輪，使用同一份卡片。
- **擾動實驗**：對 MechCAL 和基線的真實提交，執行竄改數值、換成其他分子的結果、把結論說反、刪除產物、注入假引用等擾動，加上改寫措辭和調換順序這兩種對照；檢查第一層確定性檢查和第二層評審的分數是否按預期變化。這是回應 R1 的核心實驗。

### W2.6 第 2 週的驗證
- 開發集再跑一輪（17 × 2），比較 W2.1～W2.3 的效果。
- 輸出一份開發階段報告：各家族的證據改善、偏差變化、擾動實驗的結果、基線的對比。

## 5. 刻意不做的事
- 「家族 → 測試」的對照字典；按機制命名的配方。
- 為了讓某個家族更容易得分而修改評分標準（RADIATIVE 的問題放回評分標準審閱一起處理）。
- 在測試集上運行任何東西（命令行和批量工具已鎖住）。
