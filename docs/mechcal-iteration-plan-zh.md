# MechCAL 迭代計劃（在數據集重建之前）

2026-11-13。前提：現有數據集（raw_v2_119）的排名分數不足以作為開發依據：只看 SMILES 相似度就有 R@3 0.56，分布偏斜（PACKING 出現在 75/119 個案例的參考答案），樣本量小。數據集之後會重建得更多元、更合理。

## 目標

讓 MechCAL 成為一個**本身站得住**的系統：教授在自我思考下選擇實驗、比較機制、給出有根據的解釋。這個系統之後要換一個更好的數據集仍然適用，所以不能是迎合現在這個數據集的版本。

## 開發依據：以和數據集無關的訊號為主

| 訊號 | 衡量什麼 | 和數據集的關係 |
|---|---|---|
| 證據可靠性（擾動實驗） | 竄改數值、換分子結果、把結論說反時，分數是否按預期下降；改寫措辭時是否不變 | 無關：只看證據和產物是否一致 |
| 有根據率、編造率 | 計算型陳述是否都能對上產物 | 無關 |
| 區分性 | 支持某家族的證據，是否對大多數分子都會出現（越普遍越沒區分力） | 只用工具結果，不用標籤 |
| 重複運行的穩定性 | 同一分子兩次運行的排名差異 | 無關 |
| 協議和成本 | 浪費的委派、攔截、自修成功率、時間、tokens | 無關 |
| 與基線的相對表現 | 和 Direct、ReAct（同一份卡片）相比 | 用標籤，但比較的是方法之間的差距 |
| 排名分數 | nDCG、ES-nDCG、各家族的精確率和召回率 | 依賴標籤，**只作粗略參考** |

**規則**：不根據單一案例的結果修改系統；每個改動記入 `docs/dev-decision-log.md`，並註明它是否受開發結果影響；排名分數變好但其他訊號變差的改動，不採納。

## 第一輪（C1）

- **C1a 修補**：片段分析加上淨轉移和同片段比例，並說明對稱離域的含義；補上三個配方缺少的參數。
- **C1b 先驗與證據分開推理**：board 上每個家族記錄兩件事，都由教授自己判斷、系統不寫死權重：
  - 只看結構和化學常識得出的**先驗**；
  - 每條證據的**區分性**：這個觀測對大多數分子都會出現，還是能把這個分子和其他分子區分開。

  排名要說明「先驗 × 證據」怎麼結合。Critic 加一項檢查：前三名的證據是否只是普遍存在的觀測。
- **C1c 評估流程**：
  - Direct 和 ReAct 基線在開發集上各跑一輪；
  - 擾動實驗在 MechCAL 和 ReAct 的真實提交上跑一輪（取部分案例，控制評審成本）。
- **C1d 驗證**：開發集 17 × 2，連同基線和擾動結果，出一份本輪報告。

## 之後的輪次（依前一輪結果決定）

- 第二層工具（ESIPT 互變異構體態、沿距離的激子耦合）：只在 C1 消除了「證據易得即高估」的偏差之後才做。
- 第三層（激發態受力、重金屬三重態或開殼層路線、HOST_GUEST）：逐項評估可行性。
- 任何新工具都先用區分性訊號檢查：它產生的「支持證據」是否對大多數分子都成立。

## 什麼時候暫停、轉去改數據集

同時滿足以下條件時，就暫停 MechCAL 的開發：
1. **系統穩定**：沒有中斷；有根據率接近 100%、編造率接近 0；浪費的委派接近 0。
2. **證據可靠**：擾動實驗顯示分數會隨證據被破壞而下降，隨措辭改寫而不變；MechCAL 的可靠性不低於 ReAct。
3. **沒有已知的系統性偏差**：「證據易得就高估」的模式已經消除，或者已經弄清楚它來自數據集或任務本身。
4. **剩下的錯誤主要來自數據集或任務**：例如機制取決於 SMILES 看不到的實驗條件、標籤分布偏斜，而不是系統的 bug 或推理缺陷。
5. **評估流程可以直接換數據集**：基線、擾動實驗、按家族統計、按論文 bootstrap 都能在開發集上端到端運行。

達到這些條件後，再在這個數據集上提升排名分數，邊際價值很低，而且有過擬合的風險。
