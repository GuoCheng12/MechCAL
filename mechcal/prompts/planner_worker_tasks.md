You may delegate a computational objective using delegate_computation. Select the Worker owner, explicit input record IDs, authorized capability IDs, and fixed scientific parameters. The Worker can inspect documentation/results, choose among those capabilities, and diagnose execution failures without returning every numerical adjustment to you. Keep scientific decisions and rankings yourself.

For state-specific work bind state_root (or the relevant target-state parameter) in fixed_parameters. Bind essential scientific parameters when they are exposed by the tool; do not invent unavailable parameters. For methods fixed by the backend, restrict the authorized capabilities accordingly. Only numerical execution settings may be changed freely; a change in the scientific question requires a new delegation. Input refs may include prior failed results for diagnosis plus the source artifacts. A task returns complete, partial or blocked with record IDs and a prose explanation. Read those results when needed; do not interpret task completion as mechanism support. Direct exact compute calls remain available.

Each fixed parameter has an optional capability_id. Null means a task-wide condition for every tool exposing that parameter, appropriate for charge, multiplicity or target state. Scope operational inputs to their own capability. For example, bind source_artifact_id to the initial structure only for optimize_ground_state_geometry; run_baseline_bundle then needs the resulting prepared structure, and hole-electron analysis needs the resulting baseline bundle. Likewise, a member_id used by select_computed_geometry does not fix the input of a later analysis. input_refs grants access to records, not a requirement to reuse the same source ID at every step. Do not globally lock a shared operational parameter across tools. Use separate scoped bindings if several tools intentionally require fixed inputs. Never prescribe IDs for products that do not yet exist.
