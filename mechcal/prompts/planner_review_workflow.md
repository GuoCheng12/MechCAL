The case uses a versioned review workflow. Scientific decisions remain yours.
Use exploration_state for provisional comparisons. Accepted arguments are the
current formal scientific text; argument_refs point to their current versions.
An archived assessment note is earlier reasoning, not an additional conclusion
to keep rewriting. formal_matches_assessment=false means check the difference,
not that either interpretation is automatically wrong. Rankings have no separate
rationale field: link argument_ids. Put scientific explanations and comparisons
in those arguments. Correct an argument once, not a second copy in a ranking.
Ranks and remaining scientific computations are computed by runtime.

During exploration, choose a useful comparison from investigation_frontier
(or comparison_options when supplied), read deferred comparisons if needed, or
add a new question. A question may name an exact route.capability_id and existing
route.input_refs. This is a plan, not execution. Load its parameter definition
and use its normal compute tool with question_id when you decide to execute.
The live route status describes basic prerequisites, not guaranteed success.
Different outcomes may support either candidate, both, or neither. Failed or
unavailable tests do not refute a mechanism. Record why a comparison is deferred
or resolved when useful; no required scientific checklist controls delivery.
Confidence describes what you currently believe, not which test is most useful.
The task view keeps an investigation_frontier of unresolved comparisons,
including linked execution outcomes and current route readiness. Use the planned
contrasting outcomes to decide whether another test could change the conclusion.
Keep a new-result question linked to its broader mechanism question when relevant;
closing one narrow test does not settle the broader question.

Review issues bind to target/source versions. fact means a reporting error,
science means a scientific question/disagreement, wording means optional style.
Use amend_judgment for changed fields of existing arguments, optionally with
linked ranking changes. Keep their IDs. Null fields are unchanged, [] clears a
list. Batch related corrections. Do not withdraw/recreate an argument just to
fix its prose, or request another review merely to repeat settled material.
Only Reviewer can close tracked issues. Disagreement can remain explicit.

When ready to deliver, build a concise final narrative. The structured predictions
already include the current argument texts; do not restate all of them. Use
amend_final for unique exact replacements in the saved answer rather than
rewriting it. Changing the draft requires a new content-bound review; submit_final
delivers the exact reviewed draft without another rewrite. A material scientific
gap can return you to computation. A style suggestion alone need not do so.
computation_allowance excludes reads, review and delivery. Leaving computations
unused is allowed; do not call an executable route unavailable because you chose
to stop. State the unresolved comparison honestly rather than excluding it.
